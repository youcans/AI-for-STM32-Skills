# STM32 编程任务规划 Skill

## 1. 输入规范

### 1.1 需求描述

`<project-name>` 为 Skill 调用时指定的项目名称参数。

项目目录固定为：

`C:\STM32\<project-name>`

### 1.2 输入文件

读取以下项目文件：

- `docs/requirements/proj_requirements.md`
- `docs/analysis/proj_init_scan.md`

## 2. 输出规范

### 2.1 编程任务清单

编程任务清单用于根据项目需求和初始工程分析结果，规划后续代码实现任务，为 `stm32-code` Skill 提供任务依据。

文件内容包括：

- 初步编程任务清单；
- 编程任务详细说明；
- 任务实施关系；
- 规划结论。

文件格式采用当前 Skill 目录下的任务清单模板：

`assets/proj_tasks.tpl.md`

生成文件保存至：

`docs/tasks/proj_tasks.md`

## 3. 执行步骤

### 3.1 检查已有任务清单

1. 检查 `docs/tasks/proj_tasks.md` 是否存在。
2. 如果文件存在，询问用户是否继续规划并覆盖原有文件。
3. 如果用户选择退出，则进入异常出口。

### 3.2 生成初步编程任务清单

1. 读取项目任务需求文件和初始工程分析文件。
2. 根据功能目标和当前工程状态，确定需要新增或修改代码的实现任务。
3. 任务统一采用 `T01、T02、T03……` 连续编号，编号同时表示当前建议的实施顺序。
4. 为每项任务生成：
   - 任务编号；
   - 任务名称；
   - 任务概要。
5. 任务概要仅说明当前任务需要完成的主要阶段性目标，不进入具体代码实现。
6. 生成完整初步任务清单后，提交开发者集中审阅确认。

### 3.3 细化编程任务

1. 根据开发者确认后的任务编号和实施顺序，逐项细化编程任务。
2. 每项任务明确：
   - 任务目标；
   - 涉及文件；
   - 实施要点；
   - 验证要求。
3. 实施要点应明确相关文件中的函数、代码区域或代码职责需要完成的处理，不展开具体代码设计。

### 3.4 生成编程任务清单文件

1. 根据任务规划结果，按照 `assets/proj_tasks.tpl.md` 生成编程任务清单。
2. 将生成文件保存至 `docs/tasks/proj_tasks.md`。

## 4. 任务拆分要求

1. 任务应围绕相对完整的阶段性目标进行划分。
2. 如果若干文件创建、接口建立和工程接入工作共同构成一个完整的程序基础，应作为一个整体任务进行规划，不按照单个文件、单个函数或单个修改点机械拆分。
3. 业务功能任务应围绕相对完整的实现目标进行划分，不按照代码文件、函数数量或修改位置机械拆分。
4. 每项任务应目标明确，并能够独立验证。
5. 编译、烧录和运行验证属于代码任务的验证方式，不单独列为任务。

## 5. 边界约束

1. 不得修改 CubeMX 配置、工程文件和源代码。
2. 规划结果仅以当前项目需求文件和初始工程分析文件中的实际内容为依据，不使用其它文件。
3. 不得自动补充或猜测无法确认的信息。
4. 不进行具体代码设计，不生成代码实现方案。

## 6. 出口规范

### 6.1 正常出口

满足以下条件进入正常出口：

1. 编程任务规划完成。
2. 编程任务清单保存至 `docs/tasks/proj_tasks.md`。

如果进入正常出口，输出执行情况和任务规划摘要，并提示：

【下一步建议：
- 调用 `stm32-code` Skill 按任务清单逐项实施代码修改。】

调用 `stm32-log` Skill。

### 6.2 异常出口

不满足正常出口条件时进入异常出口。

如果进入异常出口，输出未完成原因和当前执行状态，并调用 `stm32-log` Skill。
