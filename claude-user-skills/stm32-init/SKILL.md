# STM32 初始化 Skill

## 1. 输入规范


### 1.1 需求描述

`<project-name>` 为 Skill 调用时指定的项目名称参数。

`<user-description>` 为 Skill 调用时可选的用户需求描述文件参数。如果提供该参数，则读取对应文件获取实验任务描述和相关信息。


### 1.2 开发板信息

开发板型号 `<board-name>`：从用户需求描述文件获取，或通过交互方式确认。

`<board-name>` 仅支持：

- `nucleo-g431rb`
- `nucleo-c542rc`


### 1.3 硬件资料

硬件资料由 AI4MCU 硬件资料库提供。

硬件资料路径：

`C:\STM32\hardware\<board-name>`

根据 `<board-name>` 读取对应硬件概述文件：

- `nucleo-g431rb` 对应 `hardware_overview_g431rb.md`
- `nucleo-c542rc` 对应 `hardware_overview_c542rc.md`

必要时，根据项目需求读取硬件资料目录中的其它硬件资料文件。


## 2. 输出规范

### 2.1 项目目录格式规范

    <project-name>/
    ├── docs/
    │   ├── tmp/             # 保存临时文件
    │   ├── requirements/    # 保存正式项目任务需求文件
    │   ├── analysis/        # 保存项目分析和设计文件
    │   ├── tasks/           # 保存任务规划和执行文件
    │   └── <project-name>_log.md  # 保存项目开发日志


### 2.2 项目任务需求文件格式规范

项目任务需求文件用于描述当前 STM32 项目的实验任务、功能要求和相关硬件定义。

文件内容包括：
- 项目信息；
- 项目功能要求；
- 硬件定义；
- 待确认事项。

文件格式采用当前 Skill 目录下的项目任务需求文件模板：
`assets/proj_requirements.tpl.md`

用户确认后的正式项目任务需求文件保存路径：
`docs/requirements/proj_requirements.md`


## 3. 执行步骤

### 3.1 初始化项目目录

1. 检查 `C:\STM32\<project-name>` 项目目录是否存在。
2. 如果目录已存在，询问用户是否继续使用已有目录。
3. 创建项目目录结构。
4. 创建项目开发日志文件：`docs/<project-name>_log.md`。
5. 写入开发日志文件初始内容：

```markdown
# STM32开发日志

项目名称：<project-name>

## 开发记录
```


### 3.2 获取用户需求描述

1. 检查是否提供 `<user-description>`。
2. 如果提供用户需求描述文件，则读取并提取实验任务、功能要求、硬件需求等信息。
3. 如果未提供用户需求描述文件，或信息不完整，则通过交互方式获取。


### 3.3 获取硬件资料

1. 根据 `1.3 硬件资料` 的定义，读取对应开发板的硬件概述文件。
2. 根据项目需求，从硬件概述文件中提取相关硬件信息。
3. 必要时，读取 `C:\STM32\hardware\<board-name>` 目录中的其它硬件资料文件。
4. 如果项目需求与硬件资料存在冲突，提示用户确认，以用户确认结果为准。


### 3.4 生成项目任务需求文件

1. 根据用户需求描述和硬件资料，使用项目任务需求文件模板生成项目任务需求文件。
2. 将生成文件保存至：`docs/tmp/proj_requirements.md`。
3. 提示用户审阅临时项目任务需求文件，并根据用户确认结果处理：
   - 确认后保存为正式项目任务需求文件；
   - 修改后根据用户修改意见重新生成；
   - 不确认时进入异常出口。


## 4. 边界约束

1. 本 Skill 仅负责项目初始化和需求准备，不负责项目分析、任务规划和代码实现。
2. 硬件信息以 AI4MCU 硬件资料库内容为依据。
3. 未确认的信息不得自动补充。


## 5. 出口规范

### 5.1 正常出口

满足以下条件进入正常出口：
1. 项目目录创建完成。
2. 用户确认项目任务需求文件，并保存为正式项目任务需求文件。

如果进入正常出口，输出执行情况和任务摘要，并提示：
【后续开发流程：
- 使用 STM32CubeMX 完成硬件配置，并生成初始工程；
- 调用 `stm32-scan` Skill 进行初始工程分析。】

调用 `stm32-log` Skill。。

### 5.2 异常出口

不满足正常出口条件时进入异常出口。

如果进入异常出口，输出未完成原因和当前执行状态，并调用 `stm32-log` Skill。
