# STM32 代码实现 Skill

## 1. 输入规范

### 1.1 需求描述

`<project-name>` 为 Skill 调用时指定的项目名称参数。

`<task-id>` 为 Skill 调用时指定的编程任务编号，例如 `T01`、`T02`。

项目目录固定为 `C:\STM32\<project-name>`。

### 1.2 输入文件

读取以下项目文件：

- `docs/tasks/proj_tasks.md`
- `docs/analysis/proj_init_scan.md`

根据 `proj_tasks.md` 中 `<task-id>` 对应任务规定的涉及文件，读取当前任务需要修改的 `.c` 和 `.h` 源码文件。

## 2. 输出规范

### 2.1 代码修改

按照 `proj_tasks.md` 中 `<task-id>` 对应任务的规定，直接修改当前任务涉及的源码文件。

代码修改仅限当前任务明确规定的文件、函数、用户代码区域或其它代码范围。

### 2.2 执行结果

代码修改完成后，输出当前任务的代码修改摘要，并显示 `proj_tasks.md` 中该任务规定的验证要求。

## 3. 执行步骤

### 3.1 读取编程任务

1. 读取 `docs/tasks/proj_tasks.md`，定位 `<task-id>` 对应的编程任务。
2. 明确当前任务的任务目标、涉及文件、实施要点和验证要求。
3. 读取 `docs/analysis/proj_init_scan.md`，获取与当前任务代码实施相关的初始工程信息。
4. 读取当前任务涉及的 `.c` 和 `.h` 源码文件。

### 3.2 确定代码修改内容

根据当前任务的任务目标和实施要点，明确需要修改的文件、函数、用户代码区域或其它代码范围，以及需要完成的代码处理。

`proj_tasks.md` 中当前任务的规定作为本次代码修改的实施依据。

### 3.3 实施代码修改

按照当前任务要求直接实施代码修改。

代码实现细节可以根据当前源码自主确定，但不得自行改变：

- 当前任务目标；
- 修改文件范围；
- 函数或代码区域范围；
- 当前任务规定的主要处理关系。

不得增加当前任务未涉及的程序功能，不得同时实施其它编程任务。

修改 STM32CubeMX 生成的源码时，应在当前任务规定的代码范围内进行，并遵守工程已有的用户代码保护方式。

## 4. 边界约束

1. 仅允许修改 `proj_tasks.md` 中当前 `<task-id>` 任务明确规定的文件和代码范围，不得修改当前任务未涉及的文件、函数或代码区域。
2. 不得修改 CubeMX 配置，不得实施其它编程任务，不得修改 `proj_tasks.md` 和 `proj_init_scan.md`。
3. 本 Skill 不进行代码验证，不得自动调用工具执行构建、编译、工程生成或烧录。

## 5. 出口规范

### 5.1 正常出口

满足以下条件进入正常出口：

1. 当前 `<task-id>` 规定的代码修改完成。
2. 修改内容未超出当前任务规定的文件和代码范围。

如果进入正常出口，输出任务完成摘要，并显示 `proj_tasks.md` 中当前任务的验证要求。

最后调用 `stm32-log` Skill，并结束本 Skill。

### 5.2 异常出口

不满足正常出口条件时进入异常出口。

如果进入异常出口，输出未完成原因和当前执行状态。

最后调用 `stm32-log` Skill，并结束本 Skill。
